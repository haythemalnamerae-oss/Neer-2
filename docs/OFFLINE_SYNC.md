# المزامنة دون اتصال — Neer-2

**التاريخ:** 2026-11-13  
**الحالة:** طابور أحداث PWA مضاف؛ لا يزال اختبار الاستعادة والتشغيل الميداني مطلوباً.

## التنفيذ
- `src/lib/operations/taskEventOutbox.ts` يخزن الحدث في IndexedDB قبل الإرسال.
- UUID ثابت لكل حدث، مع هوية المستخدم والمؤسسة والمهمة ومسار API والحمولة وعدد المحاولات وآخر خطأ.
- إرسال FIFO حسب وقت الإدراج؛ عند فشل حدث يتوقف إرسال الأحداث اللاحقة لتجنب تجاوز الترتيب.
- إعادة المحاولة عند عودة الشبكة وفتح التطبيق/عودة التبويب للواجهة.
- لا يحذف الحدث من الطابور إلا بعد نجاح استجابة الخادم.
- الأحداث المحفوظة لحساب سابق لا ترسل بحساب آخر؛ تتم تصفيتها حسب userId وorganizationId.

## حالات الطابور
- pending: ينتظر الإرسال أو إعادة المحاولة.
- blocked: رفض دائم من الخادم ويوقف إرسال الأحداث اللاحقة للحساب نفسه حتى المعالجة.
- synced: لم يعد الحدث موجوداً في الطابور بعد تأكيد الخادم.

## حدود مهمة
- IndexedDB ليس تشفيراً مستقلاً للبيانات عند السكون؛ يعتمد على حماية الجهاز/المتصفح. لا تحفظ الطوابير رموز جلسات.
- لم تنفذ بعد شاشة إدارية لمعالجة blocked أو واجهة حالة مزامنة متكاملة داخل بطاقة المهمة.
- لا يوجد بعد اختبار إغلاق/إعادة تشغيل Android حقيقي أو WorkManager أصلي.
- لا يمكن تأكيد اكتمال سلسلة إجراءات ميدانية دون اتصال من الواجهة الحالية؛ تحديث الحالة المحلية التفاؤلي وتفعيل أزرار الخطوات التالية غير مكتمل.
- يلزم عدم مسح بيانات الموقع/التطبيق قبل مزامنة الطابور.


## تحسينات 2026-11-13
- إعادة قراءة FIFO بعد كل حدث، وإعادة تشغيل flush إذا وصل حدث أثناء تفريغ سابق.
- وقت إدراج monotonic عند تساوي ساعة الجهاز، لمنع خلط ترتيب الأحداث المتتابعة.
- منع انتقال lifecycle ثانٍ للمهمة نفسها ما دام السابق pending/blocked؛ لا يوجد تحديث تفاؤلي محلي لحالة المهمة بعد.
- شريط حالة في سجل المهام والخريطة وتفاصيل البطاقة، مع إظهار سبب الرفض وإعادة المحاولة.
- 409 يصنف رفضاً دائماً يتطلب معالجة التعارض، ولا يعاد إرساله تلقائياً.

- تمت ترقية IndexedDB إلى version 2؛ مخزن meta يخصص sequence ذريًا مشتركًا بين التبويبات، وتستخدم الأحداث القديمة التي لا تحتوي sequence ترتيب createdAt كمسار توافق.
- انتقال lifecycle ثانٍ للمهمة نفسها ممنوع محلياً حتى يزول الحدث المعلق/المحظور، لتجنب تعارض حالة المهمة المعروضة.

- أصبحت كل طلبات `/tasks/lifecycle` تتطلب UUID ثابتاً؛ لا يعتمد الخادم على UUID عشوائي يولده عند غياب المفتاح.
- POST العام إلى `/task-events` يرفض payload غير الصالح قبل تمريره إلى PostgREST.
