# المزامنة دون اتصال — Neer-2

**التاريخ:** 2026-11-15  
**الحالة:** تسلسل lifecycle وProjection محلي لجلسات الوقت مضافان؛ اختبار IndexedDB والمتصفح وإعادة فتح التبويب ما زال مطلوباً.

## التنفيذ
- `src/lib/operations/taskEventOutbox.ts` يخزن الحدث في IndexedDB قبل الإرسال.
- UUID ثابت لكل حدث، مع هوية المستخدم والمؤسسة والمهمة ومسار API والحمولة وعدد المحاولات وآخر خطأ.
- إرسال FIFO حسب sequence؛ الحدث blocked يوقف الأحداث اللاحقة للمهمة نفسها، ولا يمنع المهام الأخرى.
- إعادة المحاولة عند عودة الشبكة وفتح التطبيق/عودة التبويب للواجهة.
- لا يحذف الحدث من الطابور إلا بعد نجاح استجابة الخادم.
- الأحداث المحفوظة لحساب سابق لا ترسل بحساب آخر؛ تتم تصفيتها حسب userId وorganizationId.

## حالات الطابور
- pending: ينتظر الإرسال أو إعادة المحاولة.
- blocked: رفض دائم من الخادم؛ يوقف الأحداث اللاحقة للمهمة نفسها، بينما يسمح بمتابعة مهام أخرى للمستخدم نفسه.
- synced: لم يعد الحدث موجوداً في الطابور بعد تأكيد الخادم.

## حدود مهمة
- IndexedDB ليس تشفيراً مستقلاً للبيانات عند السكون؛ يعتمد على حماية الجهاز/المتصفح. لا تحفظ الطوابير رموز جلسات.
- لا توجد شاشة إدارية مركزية لمعالجة blocked؛ يوجد شريط حالة وإعادة محاولة، ويظل سبب الرفض بحاجة إلى معالجة من المستخدم/المشرف.
- لا يوجد اختبار متصفح حقيقي بعد إغلاق التبويب وإعادة فتحه واستعادة طابور IndexedDB.
- أضيف إسقاط محلي مؤقت لحالة جلسة الموظف من أحداث Outbox المعلقة/المحظورة وتحديث الواجهة عند تغير الطابور؛ لم يثبت بعد باختبار متصفح/IndexedDB، لذلك لا يعد قبولاً تشغيلياً.
- يلزم عدم مسح بيانات الموقع/التطبيق قبل مزامنة الطابور.


## تحسينات 2026-11-13
- إعادة قراءة FIFO بعد كل حدث، وإعادة تشغيل flush إذا وصل حدث أثناء تفريغ سابق.
- وقت إدراج monotonic عند تساوي ساعة الجهاز، لمنع خلط ترتيب الأحداث المتتابعة.
- يسمح بتسلسل عدة انتقالات lifecycle للمهمة نفسها أثناء الانقطاع، مع sequence ذري مشترك وترتيب FIFO؛ الحدث blocked وحده يوقف ما بعده للمهمة نفسها.
- شريط حالة في سجل المهام والخريطة وتفاصيل البطاقة، مع إظهار سبب الرفض وإعادة المحاولة.
- 409 يصنف رفضاً دائماً يتطلب معالجة التعارض، ولا يعاد إرساله تلقائياً.

- تمت ترقية IndexedDB إلى version 2؛ مخزن meta يخصص sequence ذريًا مشتركًا بين التبويبات، وتستخدم الأحداث القديمة التي لا تحتوي sequence ترتيب createdAt كمسار توافق.
- انتقالات lifecycle المتتابعة للمهمة نفسها تحفظ في Outbox بالترتيب؛ عند فشل حدث دائم يصبح blocked وتظل الأحداث اللاحقة للمهمة معلقة حتى المعالجة.

- أصبحت كل طلبات `/tasks/lifecycle` تتطلب UUID ثابتاً؛ لا يعتمد الخادم على UUID عشوائي يولده عند غياب المفتاح.
- POST العام إلى `/task-events` يرفض payload غير الصالح قبل تمريره إلى PostgREST.


### تصحيحات 2026-11-13
- عملية إضافة الحدث + تخصيص sequence تتم داخل transaction واحدة متعددة المخازن؛ يسمح بتتابع lifecycle، بينما يضمن flush FIFO ويوقف ما بعد الحدث blocked للمهمة نفسها.
- HTTP 401 لا يحظر الحدث نهائياً؛ يبقى pending حتى عودة جلسة صالحة. 408/429/5xx وانقطاع الشبكة تبقى قابلة لإعادة المحاولة.
- انتقالات lifecycle لا يسمح بتسجيلها عبر CRUD العام؛ تستخدم endpoint/RPC الذري حتى لا يسجل حدث دون تحديث حالة المهمة.


### تصحيح ترتيب الأحداث — 2026-11-15
- عُدّل اختيار الحدث التالي في `flushTaskEventOutbox`: الحدث المحظور يمنع إرسال الأحداث اللاحقة للمهمة نفسها، ولا يمنع المهام الأخرى للمستخدم نفسه.
- يظل ترتيب FIFO محفوظًا بين الأحداث القابلة للإرسال، وتبقى الأحداث التابعة للمهمة المحظورة محفوظة حتى تصحيح السبب وإعادة المحاولة.
- لم يُشغّل اختبار متصفح/IndexedDB فعلي لهذا التعديل؛ يلزم اختبار مهمة A محظورة ومهمة B معلقة للتأكد من استمرار B مع بقاء أحداث A.


### جلسات وقت الموظفين — 2026-11-15
- مسارات المهام غير الميدانية تسجل بدء/إيقاف/استئناف/إغلاق وقت الموظف في `/tasks/time-session` عبر الطابور نفسه، مع UUID مستقل ثابت لكل إجراء.
- أحداث GPS الميدانية لا تضيف طلب جلسة منفصلاً؛ RPC `record_field_task_event` يسجل حدث GPS وجلسة الموظف داخل معاملة واحدة. هذا يمنع أن ينجح أحدهما ويفشل الآخر.
- تسجيل نتيجة المهمة عبر `record_task_outcome_bundle` يغلق جلسة صاحب النتيجة ضمن معاملة النتيجة.
- الحدث المحظور للمهمة يمنع أحداثها اللاحقة، بما فيها جلسة الوقت، بينما تواصل المهام الأخرى المزامنة.
- واجهة الجلسات تقرأ من الخادم؛ لا تُنشأ جلسة عمل محلية باعتبارها مؤكدة قبل تأكيد الخادم. تبقى الأوامر المعلقة ظاهرة عبر حالة الطابور الحالية.
- ما زال اختبار offline E2E لتسلسل start/pause/resume/stop بعد انقطاع الشبكة وإعادة فتح التطبيق مطلوبًا؛ لم يُنفذ في هذه الجولة.

### تسلسل Offline المحلي — تحديث 2026-11-15
- أزيل منع إدراج انتقال ثانٍ للمهمة نفسها؛ يسمح الآن بتسلسل start → pause → resume → stop أثناء انقطاع الشبكة.
- يخصص Outbox sequence ذريًا داخل معاملة IndexedDB، ويظل flush يرسل أول حدث pending للمهمة حسب الترتيب. إذا أصبح حدث للمهمة blocked، يتوقف ما بعده للمهمة نفسها فقط، وتستمر المهام الأخرى.
- أضيف `getTaskOutboxEvents(taskId)`، وتدمج `getTaskTimeSessions` الجلسات المؤكدة من الخادم مع أحداث الوقت المعلقة/المحظورة للمستخدم الحالي لتكوين حالة محلية مؤقتة تظهر في تفاصيل المهمة والخريطة.
- يتم تحديث العرض عند `neer-task-outbox-change`. عند blocked تُخفى أزرار الانتقال حتى إعادة المحاولة/المعالجة، ولا تعتبر الحالة المحلية دليلاً على قبول الخادم.
- إذا تعذر جلب جلسات الخادم مع وجود أحداث lifecycle محلية، يعرض التطبيق الإسقاط المحلي؛ أما إذا لم توجد أحداث محلية فيظل خطأ القراءة ظاهرًا.
- لم يُختبر هذا التدفق بعد في متصفح فعلي/IndexedDB أو بعد إغلاق التبويب وإعادة فتحه؛ يبقى اختبار قبول إلزامياً.


### تصحيح أخطاء القراءة وGPS في الويب — 2026-11-15
- لا يُستخدم الإسقاط المحلي لجلسات الوقت لإخفاء HTTP 401/403 أو أخطاء الخادم؛ يسمح به فقط عند فشل الشبكة من نوع TypeError مع وجود أحداث lifecycle محلية.
- التقاط GPS في واجهة الويب يتم عند الإجراء الصريح عبر Browser Geolocation، ولا توجد متابعة خلفية أو دورية للموقع.

- يحتفظ خطأ API برمز HTTP في كائن الخطأ؛ يصنف الطابور 4xx الدائمة كـblocked حتى لو أرسل الخادم رسالة مخصصة، بينما 401/408/429/5xx تبقى قابلة لإعادة المحاولة.
