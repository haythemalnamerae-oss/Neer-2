# اختبارات المرحلة الثانية — Neer-2

**التاريخ:** 2026-11-13  
**الفرع:** main

## تحقق آلي/قاعدي تم
- تأكيد وجود دالتي `record_field_task_event` و`update_task_lifecycle` بالتواقيع الجديدة.
- تأكيد أن الأولى SECURITY INVOKER والثانية SECURITY DEFINER مع تحقق صلاحيات المهمة وعضوية المؤسسة داخل جسم الدالة.
- تأكيد وجود مفاتيح idempotency وإعادة الفحص بعد قفل صف المهمة.
- تأكيد أن `task_events` مفعّل عليه RLS.
- تأكيد عدم وجود امتيازات UPDATE/DELETE/TRUNCATE مباشرة لـanon أو authenticated على `task_events`.
- تأكيد سياسة قراءة الأحداث تستخدم `private.can_access_task(...,'view')`.
- تأكيد سياسة الإدخال تربط actor بـ`auth.uid()` وتتطلب `tasks.edit`.
- ترحيلات GPS وتقوية نطاق الوصول وإعادة المحاولة المتزامنة موجودة في سجل Supabase.

## لم يُختبر بعد
- لا يوجد اختبار إيجابي كامل بدورين Auth حقيقيين على مهمة فعلية.
- لا يوجد اختبار جهاز Android فعلي أو جسر أصلي.
- لا يوجد اختبار إغلاق التطبيق/إعادة تشغيل الجهاز مع استعادة الطابور.
- لا يوجد اختبار ميداني لمعدل GPS أو البطارية أو خدمة الخلفية.
- لم يشغل TypeScript lint أو بناء محلي/سحابي أو E2E؛ البناء المحلي للمالك.
- لم تختبر سلسلة بدء/إيقاف/استئناف/إنهاء عبر واجهة PWA مع اتصال مقطوع.

## حالات اختبار مطلوبة محلياً
1. مهمة field وvisit: GPS صحيح، ضعيف، غير متاح، وصلاحية مرفوضة.
2. start/pause/resume مع UUID واحد يعاد إرساله، ثم إعادة استخدامه لحدث مختلف ويجب رفضه.
3. محاولة انتقال غير صالح أو تكرار انتقال بمعرف جديد.
4. حساب موظف آخر ومؤسسة أخرى؛ يجب منع القراءة والإدخال.
5. offline enqueue ثم online flush، إعادة إرسال، إغلاق التطبيق، إعادة تشغيل الجهاز.
6. التحقق من بقاء الأحداث المعلقة وعدم إرسالها بحساب آخر.


## تحقق إضافي
- تمت مراجعة حارس `private.guard_task_state_changes` وتصحيح مسار إكمال المهمة الميدانية ليستخدم انتقال `outcome` بدلاً من `lifecycle`.
- ترحيل التصحيح موجود في سجل Supabase؛ تحقق تعريف الدالة بعد الترحيل من وجود مسار outcome.
- لم يتم إجراء اختبار كتابة إيجابي على بيانات تشغيلية؛ جداول المهام والأحداث كانت فارغة وقت الفحص.
